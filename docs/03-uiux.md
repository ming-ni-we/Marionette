## 1. 需求分析与设计输入

### 1.1 产品形态拆解

| 形态 | 本质 | 用户状态 | 设计诉求 |
|---|---|---|---|
| 创作工作室 | 重度创作工具 | 长时间盯着、反复调参、追求精确控制 | 信息密度、分组清晰、参数可推导、减少误操作 |
| 运行时引擎 | 沉浸叙事阅读器 | 长时间"读"、情感投入 | 低干扰、大行高、弱 chrome、元信息按需唤起 |
| 存储层 / 广场(v2) / 图生卫星 | 基础设施 | 后台或次级入口 | 一致的语言，不争夺注意力 |

### 1.2 已锁定的边界（约束即设计输入）

- **单机自部署优先，无账号体系** → 没有登录页、没有营销落地页 → **用户首次打开必须直接落在工作台，且首屏不能是空壳**。这是与本项目最大的一处差异化，也是竞品普遍做不好的地方（酒馆首屏即劝退）。
- **MVP = 创作 → 运行 最小闭环** → 设计优先级：① 角色卡编辑器 ② 会话运行时 ③ 工作台/内容库；三者构成主路径，其余后置。
- **国内用户中文优先** → 中文排版必须专门处理（中英混排、字重、行高、标点）。
- **对标基线 SillyTavern，但要解决其"审美粗糙 / 信息架构混乱 / 新手劝退"** → 这是本设计的核心命题（见 §2.3）。

### 1.3 设计寄存器判断（必判项）

Read `references/design-systems/design-commands.md` §1 后判定：

- **创作工作室 = Product 寄存器**：设计服务产品，标杆是"赢得熟悉感"——让 Linear / Obsidian / VS Code 的用户一眼觉得可信。因此：克制色彩（着色中性色 + 单一强调色 ≤10%）、Sans-serif 为主（Dashboard 禁止 Serif）、功能性动效（150ms 收敛）、以 UI 元素与数据而非照片承载视觉。
- **运行时引擎 = Product 寄存器（沉浸子模式）**：虽然有叙事沉浸感，但它仍是一个工具界面，不是品牌页。允许在**阅读区正文**这一个局部放宽（衬线 + 大行高 + 低对比背景），但整体不进入 Brand 寄存器的"饱和色占据 30-60% 表面积"策略。
- **平台正交轴 = web**（Windows 桌面端为主）。

> 结论：全程 **Product 寄存器**。这直接决定了后续所有动作（colorize / typeset / animate）都选 Product 一侧的答案。

## 2. 竞品 UI 调研（6 个，覆盖"工具派"与"消费派"两极）

调研对象分两类：**工具派**（SillyTavern / Chub AI / RisuAI）代表高控制力、低易用性；**消费派**（Character.AI / 星野 / 猫箱）代表低门槛、低控制力。本产品的机会区间就在两者之间。

### 2.1 SillyTavern（酒馆）—— 控制力天花板，易用性地板

**界面结构**
- 顶部图标导航栏（角色、世界书、预设等），右侧滑出面板式设计。
- 角色管理面板：Pin 面板 / 角色列表 / HotSwap 快捷栏 / 创建·导入·分组（`Create New Character`、`Import Character`、`External Import`、`Create Group`）/ 多维排序（字母·时间·使用频率·Token 数·收藏）。
- 角色编辑面板：头像 + **Token 计数** + Stats + 标签 + 收藏 + 高级定义 + 角色 lore + 聊天 lore + 导出 / 复制 / 删除 + 大量扩展选项（世界书链接、卡片 lore 导入、场景覆盖、Persona 转换、重命名、源链接、替换更新、标签导入、Gallery 视图）。
- 字段：Description、First Message、Alternate Greetings、高级定义（Main Prompt 覆盖、Post-History Instructions、作者元信息、Personality Summary、Scenario、Character's Note、Talkativeness 滑杆、Example Messages）。
- 中文教程明确把创建页分为三色区：绿=人设/场景/描述，蓝=首条对话+示例，红=动态影响提示词（可调强弱）。

**具体问题定位（本设计要解决的靶子）**

| 问题 | 病灶 | 设计对策 |
|---|---|---|
| 信息架构混乱 | 用**颜色分区**（绿/蓝/红）表达"提示词对模型的作用方式"，但**没有图例**，用户无法自行推导 | 改为**功能分组 + 渐进披露**，用标题与说明文字表达语义，颜色只用于状态不用于分类 |
| 参数暴露过度 | Depth、Role(system/user/assistant)、Token、temperature 等**工程术语全量平铺** | 术语人话化 + 高级参数折叠 + 悬浮说明；常用 5 字段前置 |
| 新手劝退 | 打开即满屏参数，无引导、无预览、无 Quick 模式 | Quick / Advanced 双模式 + 实时预览 + 首次引导 |
| 中文排版粗糙 | 中文常回退系统字体；行高按西文设；中英混排无空隙 | 专门的中文栈 + 1.6/1.75 行高 + 0.25em 中西文空隙（§4.3） |
| 审美术语缺失 | 无层级、无留白，纯表单堆叠 | 引入结构化工作台布局（§7） |

### 2.2 Chub AI —— 把"元信息/定义"二分，但仍偏原始

**界面结构**
- Character Creator 明确分两大块：**Character Info（元信息）** 与 **Character Definition（实际定义）** —— 这是一个被验证过的好模式，本设计采纳其"元信息 ≠ 影响模型"的二分思想。
- 高级定义：Alternate Greetings、System Prompt & Post-History Instructions、Character's Note、**Character Book（关键词触发式世界书）**。
- 会话侧：**Chat Tree（分支树）导航**、可切换 preset、"chat brains"。
- 评价："去装饰化"界面，学习曲线陡，选项多易过载；列表 20 条/页，浏览效率低。

**可借鉴**：元信息 / 定义的二分；关键词触发世界书的心智模型。
**要避免**：把"去装饰化"做成"无设计"；列表效率问题。

### 2.3 RisuAI —— "中间地带"定位可参考，主题策略要警惕

- Tauri 桌面 + 跨端（桌面/移动/Web），定位介于"极简界面"与 SillyTavern 复杂度之间，主打**比简单工具更强大、但比酒馆轻**。
- Display & Audio 设置：主题（Standard Risu / Waifulike / WaifuCut 视觉小说风）、文字色、图标尺寸、输入字号、侧栏宽度、动画速度。
- 高级设置：Prompt Template（main / role / jailbreak prompt）。

**可借鉴**：清晰的产品定位（中间地带）；**暴露"显示密度/字号/侧栏宽度"给用户**这一做法是对的——写进设计里（会话模式提供字号与密度调节）。
**要警惕**：WaifuCut 这类"视觉小说皮肤"是装饰性主题，会稀释品牌一致性；本项目 v1 不做多套花哨主题，只做**双主题（明/暗）+ 双密度**。

### 2.4 Character.AI —— 入门漏斗是行业标杆，长期管理是短板

**界面结构（v4.2, 2025-02）**
- 高对比**深色默认**；**持久左栏**（角色历史）；**会话窗口约占视口 65%**；**右侧面板按需呈现角色元信息**。架构上更接近"消息应用"而非 chatbot。
- 入门漏斗：未注册即先看到 Featured Characters 发现层，**中位首条消息时间 47 秒**。
- 创作：**Quick Mode**（名/头像/问候/一句话人设）vs **Advanced Mode**（长描述、背景、语气滑杆、语音、对话示例）——这是被市场验证的"分层出卡"模式，本设计采纳。
- 会话：动态问候、**swipe 换回复**、Memory（400 字/角色，可编辑）、群聊、Chat Styles。
- 移动端：底部 Tab、TikTok 式竖向 feed（Scenes / Streams / Feed）。

**可借鉴**：左栏 + 主区 + **右侧"按需"元信息面板**的三栏模型；Quick/Advanced 分层；发现先于注册。
**要避免（短板）**：会话历史管理弱、**无搜索**；群聊回合顺序 bug；记忆手动且不可靠；内容过滤破坏沉浸。

### 2.5 星野 / 猫箱 —— 消费派：门槛低、沉浸强、控制弱

**星野（MiniMax）**：二次元唯美卡面，卡面精致统一，"仙"的调性；体质上是社区 + 沉浸对话，**体力限制**与**审核**是主要抱怨点。
**猫箱（字节/豆包）**：
- **界面直接把抖音交互逻辑平移**——上下滑动切换角色卡，学习成本极低。
- 角色自定义强：40+ 形象 / 150+ 音色 / 10+ 参数；**AI 创作助手逐步引导**（性格 → 背景 → 口头禅），约 5 分钟捏完一个角色。
- **分支剧情树 + 回溯分支**：可在历史节点分叉出多条故事线。
- 缺点：免费额度限制、高峰排队。

**可借鉴**：**逐步引导式角色创建**（极大降低劝退）；**分支/回溯**作为一等公民（本产品的会话运行时必须原生支持）。
**要避免**：把角色库做成"刷短视频"——本产品是**创作工具**，不是内容消费流；信息架构要服务"找得到自己的卡"，而非"无限刷"。

### 2.6 共性提炼：设计趋势与反趋势

**行业共识（可作为收敛方向）**

1. **三栏骨架收敛**：左（导航/列表）+ 中（主区）+ 右（按需元信息）——Character.AI、Chub、ST 都收敛到这一结构。
2. **"元信息 / 定义"二分**：展示用元数据 ≠ 影响模型的定义（Chub 明确、ST 隐含）。
3. **Quick / Advanced 分层出卡**：C.AI 验证，猫箱用"引导式"变体。
4. **世界书 = 关键词触发的条目列表**：ST / Chub 一致的心智模型。
5. **分支 / 回溯的会话树**：Chub Chat Tree、猫箱分支剧情树。
6. **swipe 换回复 / 备选问候**：全行业标配。
7. **沉浸阅读 = 气泡 + 头像 + 元信息默认收起**。

**集体踩的坑（本设计的反模式清单）**

1. **把 prompt engineering 术语（system/user/assistant、Depth、jailbreak、temperature）直接暴露给创作者**——这是把内部实现成本转嫁给用户。
2. **纯自由 textarea 无结构化引导**：创作者不知道"写了会影响什么"。
3. **用颜色分类字段**（ST 的绿/蓝/红）却无图例，用户无法推导。
4. **元信息与沉浸阅读二选一**：要么全藏（C.AI 沉浸但不可控），要么全露（ST 可控但出戏）——**没有中间态**。
5. **会话历史管理弱**：无搜索、无过滤（C.AI）。
6. **中文排版失败**：回退系统字体、按西文设行高、中英混排无空隙。
7. **首屏空壳或首屏劝退**：ST 打开即参数墙。
8. **装饰性主题泛滥**（RisuAI 的多皮肤）：稀释品牌一致性，增加维护成本。

> **本产品的定位结论**：站在"工具派"与"消费派"之间——**用消费派的引导性降低门槛，用工具派的可控性留住高手**。这就是设计方向的主轴。

## 3. 设计方向与对标品牌

### 3.1 对标品牌（向专业创作工具靠，不向 SaaS 营销站靠）

| 对标 | 借用什么 | 为什么 |
|---|---|---|
| **Linear** | 键盘驱动、命令面板（Cmd+K）、克制的深色、精确的间距、无冗余装饰 | 它证明了"重功能工具也能优雅"；是"参数多但不劝退"的当代范本 |
| **Obsidian** | 本地优先、分屏、面板模型、世界书/知识库的树形管理、主题系统 | 本地优先与本项目（单机自部署）气质一致；分屏/树管理正是世界书需要的 |
| **Raycast** | 极简深色、命令式入口、信息层级用"亮度"而非"阴影" | 提供了"深色主题下如何用亮度递进表达层次"的答案 |
| **Cursor / VS Code（辅）** | 编辑器分屏、侧栏树 + 标签页 + 底部面板、设置的分组折叠 | 角色卡编辑器是"多字段表单 + 预览"，正是编辑器的经典解法 |

**为什么不向 SaaS 营销站靠（Notion 官网、ConvertKit、Landing 模板那一派）**：本项目**没有营销页**，用户是"回来干活的"，不是"被说服的"。SaaS 落地页的语言（Hero、社会证明、CTA 重复）在此处是纯噪音，且极易滑向 P0 禁止的"千篇一律 Hero"与"虚构指标"。

**为什么不用 Character.AI 作为视觉对标**：它的视觉是"消费级娱乐 app"（彩色、卡面、feed 流），与本产品"专业创作工具"的定位冲突。借它的**信息架构**（三栏、按需元信息），不借它的**视觉皮肤**。

### 3.2 视觉基调与视觉隐喻

**关键词（5 个）**：克制的 · 结构化的 · 纸面质感的 · 可聚焦的 · 可推导的

**视觉隐喻：「后台工作台 + 舞台」（Backstage Workbench + Stage）**

- **创作端 = 后台工作台**：灯是亮的，工具都摊在台面上，抽屉按功能分组，一切可触可推导。对应高密度、清晰描边、无装饰。
- **运行端 = 舞台上场**：灯暗下来，只有演员和观众。chrome 隐去，正文放大，背景变暗变静。对应低密度、大留白、弱描边。
- **同一个剧场，两种照明**——这个隐喻直接推导出 §3.3 的双密度结论，并给出了一条统一的解释：**不是两个软件，而是同一场所的两种灯光**。

> 这不是"编辑排版风"（展示衬线 + 斜体 + 小型 mono 标签 + 分隔线 + 单色克制那种 2026 年已被 AI 工具用滥的套路）。区别在于：本设计的"纸感"只体现在**会话叙事正文的字体选择**上（中文阅读用宋体是功能性选择，中文小说/出版物本就以宋体为阅读体），而**整个工具的骨架是结构化面板**，不是编辑杂志版式。

### 3.3 【关键判断】双密度方案：同一套主题的两种模式，而非两套视觉系统

**结论：同一套 Design Token 底层 + 两档密度（`studio` / `session`），通过 `data-density` 切换密度相关 Token。**

**理由（决策依据）**

1. **用户会来回切换**：创作者在"编辑角色卡"与"开一场会话试卡"之间高频往返。两套视觉系统会造成"这是两个软件"的割裂感，损伤品牌一致性。
2. **维护成本**：这是单机自部署 MVP，团队小。两套视觉系统 = 双倍 Token、双倍组件样式、双倍测试与主题回归。密度分档只需覆盖**排版与层次相关的少数字段**（字号、行高、表面层次、圆角不变），成本可控。
3. **隐喻一致性**：剧场是一个场所，只是开了不同的灯。底层色相、中性阶、圆角、动效曲线**完全共享**，只有"照明"（对比度、留白、行高、字体）变化。
4. **可控性**：用户可在会话中独立调节字号/密度（借鉴 RisuAI），因为密度是**模式属性**而非全局设置，天然支持局部覆盖。

**实现契约（交给架构师与前端）**

```
:root                          → studio 密度（默认）
[data-density="session"]       → session 密度覆盖（仅密度相关 Token）
[data-theme="light"]           → 浅色主题覆盖（与密度正交，可自由组合）
```

- **共享**：色相体系、中性阶、圆角阶梯、阴影阶梯、动效时长与缓动、z-index。
- **差异化**（只此 6 项）：
  | 字段 | studio | session |
  |---|---|---|
  | 基准字号 | 14px | 16px |
  | 正文行高 | 1.6 | 1.75 |
  | 叙事字体 | Sank（sans） | **Serif（仅正文）** |
  | 行高（列表行） | 32px 固定 | auto |
  | 表面处理 | 1px 描边 + 无阴影 | 低对比背景 + 无描边 + 大留白 |
  | 元信息 chrome | 常驻可见 | 收起为边缘指示器，点击展开抽屉 |

> 正交性保证：主题(明/暗) × 密度(studio/session) = 4 种组合，全部由同一套 Token 派生，无需额外样式表。

## 4. 配色 / 字体 / 风格方案

### 4.1 配色基调：琥珀暖光（Amber）

**主色方向**：琥珀金 `Amber` 作为唯一强调色（品牌 / "舞台暖光"），中性基底为**冷调石墨灰**（Graphite）。

**为什么是琥珀，而不是行业默认色**

| 候选 | 判定 |
|---|---|
| 紫 → 粉渐变 | **触碰 P0 红线，直接否决**（`#7C3AED → #A855F7 → #EC4899` 及 Indigo→Pink 任意组合） |
| 默认靛蓝 `#6366F1` | 业界公认"首罪"，一眼 AI（P1 严重），否决 |
| AI 惯用的紫 `#7C3AED` | 与"所有 AI 产品都长得像 ChatGPT"同质化，否决 |
| 信任蓝 `#2563EB` | 安全但无记忆点，且是 SaaS 通用色，与"专业创作工具"气质不够契合 |
| **琥珀金 Amber** | **采纳**。① 是"舞台/工作台照明"隐喻的物理颜色（钨丝灯、台灯、聚光灯）；② 在 AI 产品里罕见，差异化强；③ 暖金对创作/叙事有情绪价值（篝火、手稿、烛光）；④ 与冷调中性基底形成高质感的暖冷对比 |

> **与"紫色→粉色渐变"套路的关系（必答项）**：本方案**完全不使用任何渐变主视觉**。主视觉一律为**纯色块 + 描边**；如需渐变，仅限同色系深浅（如 `amber-400 → amber-500`）且仅用于极小面积（进度条、骨架微光），绝不用于大标题/Hero/主色面板。不使用发光边框 + 毛玻璃的三位一体。**明确避开该红线的三个特征：无紫粉渐变、无发光边框、无装饰性毛玻璃。**

**关键色值**

| 语义 | 深色主题（默认） | 浅色主题 | 说明 |
|---|---|---|---|
| `--color-bg` | `#101215` | `#F4F5F6` | 页面背景（深色非纯黑） |
| `--color-surface` | `#16181C` | `#FFFFFF` | 卡片/容器 |
| `--color-surface-raised` | `#1C1F24` | `#FFFFFF` | 抽屉/菜单/浮层 |
| `--color-fg` | `#E9EBEE` | `#1C1F24` | 主文本（浅色下非纯黑） |
| `--color-fg-2` | `#C0C5CC` | `#4A5058` | 次级文本 |
| `--color-muted` | `#8E949D` | `#676D76` | 说明/占位 |
| `--color-border` | `rgba(255,255,255,0.09)` | `#D2D5DA` | 默认描边 |
| `--color-accent` | `#E3AE3E` | `#9C6F19` | **品牌强调，每屏 ≤ 2 处** |
| `--color-accent-on` | `#0A0B0D` | `#FFFFFF` | 强调色之上的前景 |
| `--color-success` | `#57BE84` | `#1C8C4E` | 成功 |
| `--color-warn` | `#E2803A` | `#A65A18` | 警告（偏橙，与琥珀拉开） |
| `--color-danger` | `#EC6A61` | `#C43B34` | 错误/危险 |
| `--color-info` | `#6BA8DC` | `#2C6FB0` | 信息 |

**调色板四层配比**：中性色 80-88% / 强调色 5-8% / 语义色 0-4% / 效果色 <1%。

**对比度**（WCAG AA 校验）
- 深色：`fg` on `bg` ≈ 15:1；`muted` on `bg` ≈ 5.9:1；`accent-on` on `accent` ≈ 8.7:1 —— 全部通过。
- 浅色：`fg` on `bg` ≈ 14:1；`muted` on `bg` ≈ 4.7:1；`accent` on `#FFF` ≈ 4.8:1 —— 通过。
- **`--color-meta` 是低对比（浅色下约 2.9:1）**，仅用于装饰性元数据，**不得作为唯一信息载体**，且字号 ≥14px；关键信息请用 `muted` 及以上。

### 4.2 明暗主题策略：v1 **必须双主题**，深色默认

- **行业预期**：VS Code / Obsidian / Linear / Raycast / Notion 全部双主题——"工具类产品"用户对此已是硬预期，缺失会被视为不专业。深色是这类用户的默认工作环境（酒馆用户尤甚）。
- **v1 落地**：深色为默认（匹配受众习惯 + 运行端沉浸），浅色完整可用（长时间中文阅读、明亮环境下部分用户更舒适）。
- **实现**：同一套 Token，`[data-theme]` 切换，非"反相"而是**重新标定亮度**（深色 `#16181C` 系、浅色 `#F4F5F6` 系），避免直接反色造成的对比坍塌。

### 4.3 中文字体选型与排版策略

**字体栈（西文在前、中文在后——否则英文字形会被中文字体渲染坏）**

```css
--font-sans:  "Inter", "Noto Sans SC", "PingFang SC", "Microsoft YaHei", "Segoe UI", system-ui, sans-serif;
--font-serif: "Noto Serif SC", "Source Han Serif SC", "Songti SC", "SimSun", "Georgia", serif;
--font-mono:  "JetBrains Mono", "Fira Code", "SFMono-Regular", Consolas, monospace;
```

| 字体 | 用途 | 备注 |
|---|---|---|
| Inter | 西文 UI、英文标签、数字 | 只用 400/500/600；**不作为"高级展示字体"宣称**，仅作可靠 UI 字 |
| Noto Sans SC（思源黑体） | 中文 UI、正文 | 桌面端可优先落 `PingFang SC` / `Microsoft YaHei`（系统已装，零加载成本） |
| Noto Serif SC（思源宋体） | **仅会话叙事正文** | 中文文学/出版物阅读体；**禁止用于任何 UI 控件与标签** |
| JetBrains Mono | Token 计数、参数数值、快捷键 | 数字用 `tabular-nums` |

**排版策略**

| 项目 | 规则 |
|---|---|
| 字号 | 8 级：12 / 13 / 14 / 15 / 16 / 18 / 22 / 28 / 36px；创作端基准 14px，运行端正文 16→17px |
| 行高 | 中文正文 **1.6**；会话叙事 **1.75**；标题 1.25-1.4；**一律用无单位值**（不用 px 绝对值，混排更稳） |
| 字重 | 400 正文 / 500 强调·标签·表头 / 600 标题·CTA。**中文正文最小 400，标题最小 600**（中文笔画密，低字重易糊） |
| 字距 | 中文正文 **0**（全局 letter-spacing 会破坏中文结构，禁止）；标题 -0.01~-0.02em；**全大写英文标签 ≥0.06em** |
| 中英混排 | 中西文之间插 **0.25em 视觉空隙**（渲染层处理）；英文/数字可比中文大 1-2px 以平衡视觉密度 |
| 数字 | 等宽数字 `font-variant-numeric: tabular-nums`（Token 计数、参数对齐） |
| 标点 | 中文内容全角、英文/代码半角，不混用 |
| 行宽 | 会话叙事列 `max-width: 68ch`（中文约 30-34 字/行），符合 50-75 字符舒适区 |

> 为什么运行端用宋体：中文**长篇叙事**阅读，宋体（衬线）的横细竖粗与笔锋能提供比黑体更好的阅读节奏与沉浸感——这是中文出版物的既有阅读习惯，是**功能性选择**，不是装饰。它也不触碰"编辑排版风"反模式（后者指的是用展示衬线做营销页版式）。

### 4.4 风格基调

- **主风格**：Swiss Minimalism（瑞士极简）× Dark Mode（深色工作台）——对应 UI 风格库 #1 + #7。
- **辅风格**：Micro-interactions（微交互，10-15% 工时）+ Bento Box Grid（工作台内容分区，仅创作端首页）。
- **明确不用**：Aurora UI / Glassmorphism 毛玻璃 / 紫粉渐变 / Cyberpunk 霓虹 / Neumorphism / 视觉小说皮肤。

## 5. Design Token 基础层（已产出）

**产出文件**
- `design/design-tokens.json` —— 机器可读（前端 `import tokens from './design-tokens.json'`）
- `design/design-tokens.css` —— CSS 变量（前端直接 import）

**分层架构**

```
primitive（唯一 hex 来源）
   ↓ var()
semantic（语义别名：--color-surface / --color-fg / --color-accent …）
   ↓ var()
density（studio / session 仅覆盖密度字段）
```

**已覆盖的 Token 域（全部为基础层，不含页面级）**

| 域 | 内容 |
|---|---|
| 色彩阶 | Neutral 18 阶 / Amber 10 阶 / Green·Orange·Red·Blue（400/600/700）+ alpha 层 |
| 语义色 | surface / fg / border / accent / 语义状态 / focus（明暗双套） |
| 字体阶 | 3 家族（sans / serif / mono）+ 9 级字号 + 4 级字重 + 5 级行高 + 5 级字距 |
| 间距阶 | 4px 网格 11 级（0/4/8/12/16/20/24/32/40/48/64/80） |
| 圆角 | xs 4 / sm 6 / md 8 / lg 10 / xl 12 / 2xl 16 / pill |
| 阴影层级 | flat / ring / raised / overlay / modal（深色用描边，浅色用阴影） |
| 动效 | 5 级时长（80/120/160/220/320ms）+ 4 条缓动（**无弹跳**）+ reduced-motion |
| z-index | 13 级（base → tooltip） |
| 布局 | 容器宽度 / 阅读行宽 / rail·panel·drawer 宽度 |
| 断点 | 640 / 768 / 1024 / 1280 / 1536 |

**硬约束（前端必须遵守）**
1. 组件与页面**只引用 semantic 层**，禁止直接引用 primitive 变量或写死 hex（`#fff` / `#000` 除外）。
2. 缓动曲线**禁止弹跳/弹性**（如 `cubic-bezier(0.68,-0.55,0.265,1.55)`）。
3. 动画只做 `transform / opacity / color`，禁止动画 `width / height / top / left`。
4. `prefers-reduced-motion: reduce` 下所有时长归零。
5. 每屏 accent **可见使用 ≤ 2 处**。

### 5.1 Token 落地约定（React 19 + Vite 7 + Tailwind v4.1 + shadcn/ui）

- **单一真源**：`design-tokens.json` 为唯一真源；`design-tokens.css` 经 Tailwind v4 `@theme` 映射；组件只消费 Tailwind 语义类（`bg-surface` / `text-fg-2` / `border-border` / `rounded-md`），**禁止 `bg-[#xxxxxx]` 任意值**。
- **Tailwind v4 `@theme` 映射示例**
  ```css
  @import "tailwindcss";
  @import "./design-tokens.css";
  @theme {
    --color-bg:             var(--color-bg);
    --color-surface:        var(--color-surface);
    --color-surface-raised: var(--color-surface-raised);
    --color-fg:             var(--color-fg);
    --color-fg-2:           var(--color-fg-2);
    --color-muted:          var(--color-muted);
    --color-border:         var(--color-border);
    --color-accent:         var(--color-accent);
    --color-accent-on:      var(--color-accent-on);
    --radius-md:            8px;
    --spacing:              4px;   /* 4px 基准网格 */
  }
  ```
  生成 `bg-surface` / `text-muted` / `border-accent` / `gap-4` 等语义类。
- **主题与密度切换**：`<html data-theme="dark|light" data-density="studio|session">`，二轴正交。
- **shadcn/ui CSS 变量对齐**：`--background→--color-bg`、`--foreground→--color-fg`、`--card→--color-surface`、`--primary→--color-accent`、`--primary-foreground→--color-accent-on`、`--destructive→--color-danger`、`--muted-foreground→--color-muted`、`--border→--color-border`、`--ring→--color-accent-ring`、`--radius→8px`。
- **命令面板**：主路径入口用 shadcn `Command`，快捷键 **Cmd/Ctrl+K**（对标 Linear / Raycast 的入口模型）。
- **图标**：`import { GitBranch } from "lucide-react"`（具名导入，不整体导入）。

## 7. 三个核心页面的布局方向（仅结构，不画细稿）

### 7.1 工作台 / 内容库首页 —— 首屏就是工作台

**首屏是什么**：单机无账号，**首屏不是营销页、也不是空壳，而是"可以直接干活的工作台"**。

- **骨架（三区，非居中 Hero）**
  - 左：**全局导航 rail**（64px，图标+文字：内容库 / 会话 / 素材 / 设置）+ 底部"本机状态"位（替代账号位：模型连接状态、后端、存储路径）——**无登录入口**。
  - 中：**内容库主区**。顶部一条"继续上次"横向带（最近会话 + 最近编辑的卡）→ 下方分区网格：角色卡（主，大卡）/ 世界书 / 预设 / 群聊，各自一个区块，区块标题 + "查看全部"。
  - 右：可收起的**"快速开始"面板**（新建角色卡 / 导入酒馆卡 / 开一场会话）。
- **首次打开（Empty 状态 = 关键差异点）**：预置一张示例角色卡（"现代日常向"通用卡，与 PM 的垂直切片对齐）+ 三个入口（从模板开始 / 导入 SillyTavern 卡片 / 从零创建）+ 一句最短路径提示（"直接开聊"）。**绝不给参数墙，绝不给空列表**。
- **最短路径**：首屏有一个显眼的"开始会话"主操作，让"读"这件事一步可达。
- **响应式**：<768px 时 rail 收为底部 TabBar，内容库网格转单列。

### 7.2 角色卡编辑器 —— 用分屏 + 渐进披露 + 预览来"不劝退"

**核心解法：三栏分屏 + Quick/Advanced 双模式 + 实时预览**（融合 Obsidian 分屏、VS Code 设置分组、C.AI 分层、Chub 元信息/定义二分）

- **骨架**
  - 左：**字段导航**（分组目录：基础 / 人设 / 对话 / 世界书关联 / 高级）。用**文字标题分组**，**不用颜色分区**（直接修正酒馆的绿蓝红病灶）。
  - 中：**编辑表单**，按组折叠。
  - 右：**实时预览**——用真实聊天气泡渲染"当前设定会产生什么效果"（首条问候 + 一句示例回复），编辑即所见，解决"我写了这段到底影响什么"的困惑。
- **渐进披露**：常用区（头像 / 名称 / 一句话简介 / 人设描述 / 开场白）默认展开；高级区（提示词覆盖 / 权重与深度 / 发言角色 / 作者注 / 话痨度 / 备选问候）默认折叠在"高级"内。
- **Quick / Advanced 双模式**：Quick = 5 字段快速出卡（对标 C.AI/猫箱的引导式）；Advanced = 全量字段。顶部 Tab 切换，Quick 模式下高级字段不消失，只是折叠。
- **术语人话化**（直接修正酒馆的术语暴露病灶）：
  - `Depth` → "这段话对剧情的影响强度"（配滑杆 + 数值 Tooltip）
  - `Role (system/user/assistant)` → "作为谁的发言"（选项：旁白设定 / 我的立场 / 角色的立场）
  - `Token 计数` → 折叠进底部状态栏，用 mono 字体，**不进入创作流**。
- **顶部**：保存状态（已保存 / 有未保存修改）、Token 估算、导出、试开一场会话。
- **校验与状态**：字段级错误就地提示 + 摘要；空字段给"可选"而非红色错误。

### 7.3 会话运行时界面 —— 专注优先 + 元信息"按需唤起"

**核心矛盾**：沉浸阅读 vs 元信息（世界书命中/记忆/分支）共存。

**解法：默认专注，元信息降级为"边缘指示器 + 右侧抽屉"，绝不常驻挤压阅读列。**

- **阅读列**：单列居中，`max-width: 68ch`；角色消息（左，弱气泡 + 头像 + 名字）与用户消息（右，轻气泡）区分；叙事正文用 Serif + 1.75 行高 + 低对比背景 `--color-reading-surface`。
- **元信息降级**：顶部一条**细指示条**（世界书命中数 / 记忆 / 上下文占用 / 分支位置），默认只显示图标+数字，**点击才展开右侧抽屉**（`--z-drawer`，overlay 形式，不重排阅读列）。
- **分支 / 回溯**：抽屉内的**会话树视图**（时间线缩略 + 任意节点"分叉"），对标 Chub Chat Tree + 猫箱分支。分支在阅读列用一条细标记提示"此处可回溯"，不打断阅读。
- **输入区**：底部 dock，多行自适应；"旁白 / 指令"区默认折叠，展开才出现（避免污染沉浸态）。
- **沉浸模式（"舞台灯光暗下来"）**：一键隐藏所有 chrome（导航 rail、指示条、抽屉），只留正文 + 一行淡出的输入框；`Esc` 退出。**这是双密度隐喻的最终落点**。
- **用户可调**：字号、行高、阅读宽度（对标 RisuAI 的显示设置）——存到本机，无需账号。
- **状态覆盖**：生成中（流式 + 停止）、空会话（引导选卡）、错误（重试）、超长上下文（折叠 + 提示）、分支节点边界。

### 7.4 引擎可见性设计——把黑盒变白盒（架构师已提供接口）

这是本项目相对酒馆最关键的差异化之一：**让"提示词 / 世界书如何被组装"变得可见**，而不是让用户盲猜。

| 接口（架构师锁定） | UI 落点 | 设计要点 |
|---|---|---|
| `POST /worldbooks/{id}/test`（逐条命中判定） | 世界书编辑器内嵌**"命中测试"面板** | 输入一段测试文本 → 逐条返回命中/未命中 + 命中关键词 + 生效权重；用 `CircleCheck`/`CircleX` **配文字标签**，禁止仅靠颜色表达 |
| `GET /sessions/{id}/last-context`（组装后 prompt + 触发 trace + token 占用） | 会话运行时右侧抽屉的**"上下文检视"页签** | 分段展示（系统 / 人设 / 世界书 / 记忆 / 历史）+ 每段 token 数 + 命中来源高亮；mono + tabular-nums 展示计数；**仅按需展开**，不污染沉浸 |

设计价值：把酒馆"调参靠玄学"的痛点，转成"看得见因果"的可推导体验——直接兑现 §3.2 关键词中的"可推导的"。

### 7.5 SSE 流式事件 → UI 状态映射（架构师锁定事件类型）

| 事件 | UI 表现 |
|---|---|
| `world_info` | 元信息指示条世界书命中计数 +1；抽屉命中列表实时追加（来源 + 关键词） |
| `start` | 生成开始：发送按钮切 `Square` 停止态，输入禁用，正文区出现生成中占位 |
| `delta` | 正文流式追加 + 尾随光标；**预留行高，禁止布局抖动** |
| `usage` | 底部 mono 状态栏 token 占用更新（tabular-nums，数字变化不重排） |
| `image` | 会话内嵌图片消息插入 + 写入图集素材；懒加载 + 低频占位 |
| `done` | 状态复位；该条可编辑/复制/收藏/分支；滚动到锚点 |
| `error` | 就地错误条（`CircleX` + 具体文案 + 重试）；已生成内容保留不丢 |

> 原则：**流式期间仅做 `opacity` / `transform` 级视觉更新，禁止动画 `height` / `width`**；`prefers-reduced-motion` 下打字机效果降级为直接插入。
