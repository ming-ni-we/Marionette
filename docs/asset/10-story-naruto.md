```

卡卡西的眼神变了。他慢慢把《亲热天堂》塞回忍具袋。

「看来，」他说，「我们的 D 级任务，可能要从这里开始重写等级了。」
```

## 七、预设调优（《火影 · 任务推进式》）

针对**多角色轮转**与**节点判定**专门加了两条约束（调优过程见下节实测）：

### 关键约束 1 —— 一人一段，不越俎代庖

```
【最重要的规则：一人一段，不要越俎代庖】
你只负责**你被分配到的那个角色**的台词与动作。
绝对不要在**你的段落里**替其他角色说话、写其他角色的对白。
如果你认为本轮应该由别的角色接话，那是导演分配的事——
导演会把该角色单独列为一名 speaker，你不需要代劳。
```

### 关键约束 2 —— 角色轮转

```
【角色轮转】
若场上有多名在场角色，而其中某位已连续两轮以上没有独立发言，
应当由她/他接话，而不是永远由同一个人代表全队。
```

### 关键约束 3 —— 节点判定从宽

```
【节点判定】系统会给出未完成节点及其触发条件。
玩家行为一旦符合条件即应触发（node_triggered），判断从宽，不要拖延。
```

> **调优经验**：角色 `voice` 字段**写得越详细，导演输出越长**，
> 越容易撞上 `max_tokens` 上限导致 JSON 截断（详见下节 + `04-pitfalls.md` D12）。
> 因此把 voice 精简为「一句话特征」（如佐助 = 「极简短促，常用「……」和「哼」」），
> 详细人设放到 `description` / `personality`。

## 八、线上实测记录（2026-10-13）

### 8.1 首次验收 — 暴露两个引擎缺陷

真模型开演后症状：**只有卡卡西一人说话、节点永久不动、行动建议恒为空**。

定位过程：

1. 抓导演原始决策 → `"reason": "导演输出无法解析为 JSON，本轮降级为单角色接话。"`，`degraded: true`
2. 查线上日志 → `director L1 output unparsable`，**且输出被截断**
3. 对比《雾隐町》日志正常（`director decided | speakers=['c2'] node=n1`）
4. **根因**：`max_tokens` 过紧 —— 导演 512、建议 200，JSON 写不完被硬截断

### 8.2 修复（两处同源缺陷）

| 缺陷 | 位置 | 原值 | 现值 |
|---|---|---|---|
| ① 导演裁决 JSON 被截断 | `director.py` | 512 | **1024** |
| ② 行动建议 JSON 被截断 | `action_suggester.py` | 200 | **400** |

提交 `4223d28` / `0dad7ef`，镜像 `4447e9b4` → `f53bbc95`。406 tests passed / ruff 全绿。

### 8.3 修复后验收（全部通过 ✅）

| 判据 | 结果 |
|---|---|
| 导演降级 | **4/4 零降级** |
| 角色轮转 | `speakers=['c2','c1','c3']` —— 三人轮流 |
| 节点推进 | `n1 → n2` 成功触发 |
| flags | 11 个剧情标记正确写入 |
| 佐助人设 | 「雷。针。从背后。」「哼。」—— 极简短促，零 OOC |
| 行动建议 | 恢复出现，四条 `tone` 分类齐全 |
| 浏览器验收 | 26 个气泡，三人各自独立且顺序正确，**零页面错误** |

## 十、已知限制

| 限制 | 说明 |
|---|---|
| 节点判定依赖 LLM | `trigger` 是自由文本，由导演模型判断，非硬条件 DSL（BG3 式改造见对话记录） |
| 无骰子检定 | 当前无「成功率 + 骰子」机制，全部走向由 LLM 叙事决定 |
| 佐助是「编外战力」 | 设计上其去留由玩家选择影响，但**阵营切换未做显式状态机**，靠叙事服软 |
| 无物品栏 / 任务日志 | 仅有 `flags`（11 个标记），未做背包与任务 UI |

> 若要做成真正的《博德之门 3》式剧情推动，
> 需要补：**条件 DSL → 骰子检定 → 显式选项 → 物品/任务/结局状态机**（分四阶段）。
