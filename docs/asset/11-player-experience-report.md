> 依据：两场实玩复盘（雾隐町 20 轮 / 木叶·雾中之刃 20 轮）+ 前端代码逆向 + 真实 UI 截图验证。

## 一、实玩数据诊断（证据）

| 指标 | 雾隐町 | 木叶·火影 | 说明 |
|---|---|---|---|
| 玩家平均输入 | 76 字 | 103 字 | 必须写"动作+台词+意图"复合长句 |
| AI 平均输出 | 135 字 | 244 字 | AI:玩家字数比 5.1:1 / 7.6:1 |
| 复合型输入占比 | 19/20 | 20/20 | 几乎每条都要写 2 个以上意图 |
| 每轮建议动作（actions） | ✅ 3 条/轮 | ✅ 3 条/轮 | 服务端每轮都在生成 |

**三个核心问题：**

### 问题 1：建议动作"生了没人看"（最严重）
后端每轮都在 SSE 里下发 `actions` 事件——3 条带 `label + hint + tone（观察/发言/行动/移动）` 的建议，质量相当高（如「蹲下摸那串脚印的深浅——看是真脚印还是布下的饵」）。前端也有完整渲染组件（输入框上方"导演给了几个方向"芯片区）。

但实测验证：**重新打开已有会话时，建议区是空的**（`建议区标题: 0`）。因为 `actions` 只在流式生成的瞬间下发一次、存内存不落库——刷新即丢，历史会话永远看不到。玩家实际接触到的就是截图里那个空输入框：`写点什么…（Enter 发送，Shift+Enter 换行）`。

### 问题 2：输入没有"脚手架"，门槛全压在玩家身上
AI 叙事每轮抛出大量细节（水纹偏半指、绳结第三圈、脚踝临界），玩家想接住剧情就必须复述这些细节才能"被听懂"——这就是你观察到的"描述得很仔细才能推动剧情"。输入框是裸 textarea，没有任何结构化引导。

### 问题 3：角色发言被当成"小说"而非"对话"
一轮 AI 回复经常拆成 4~6 条消息（旁白→角色A→旁白→角色B→旁白），单条最长 564 字。玩家面对的是"读一篇短篇"而不是"接一段对话"，阅读负担重，也加剧了"必须写长"的错觉。

## 二、重新设计方案

### 方案总览：把输入从"写作题"改成"选择题 + 选填题"

```
现有：  [空 textarea]  → 玩家自己写 100 字
目标：  [3 个建议芯片（一键走）]
        + [芯片微调：点击后预填，可改两个字再发]
        + [裸输入框（保留，给硬核玩家）]
```

### 改造 1：建议动作持久化 + 会话恢复（P0，成本最低收益最大）

- **后端**：把每轮 `actions` 写入会话记录（`sessions.{id}.last_actions`），`GET /sessions/{id}` 一并返回；前端加载会话时 `setSuggestions(data.last_actions)`。
- **效果**：玩家任何时候打开会话，都先看到导演给的方向。**这是纯接线工作，前后端代码都已存在。**

### 改造 2：芯片点击 = 预填而非直发（P0）

当前点击芯片直接发送（`f=j=>{...t(j.label)}`）。改为：
- **单击** → 填入输入框（label 预填 + hint 作为占位提示），玩家可增删两个字；
- **双击/长按** 或芯片上的「⚡」→ 直接发送（保留现有快捷路径）。
- **效果**：一键起步 + 轻度个性化。玩家输入成本从 100 字降到 10 字，且仍保留掌控感。

### 改造 3：意图四键输入条（P1）

把已有的 `tone` 四分类（观察 observe / 发言 speak / 行动 act / 移动 move）升级为输入模式开关：

```
[🔍观察] [💬发言] [⚔️行动] [🏃移动] | 自由输入
```

- 选「发言」→ 输入框 placeholder 变为"你说什么？（一句话就够，语气导演来配）"
- 选「行动」→ "你要做什么？（写动词+对象即可，如：查脚印）"
- 提交时把 tone 作为结构化字段随 `input` 发给导演，**导演就能按意图配戏，不再要求玩家把画面细节写全**。

### 改造 4：导演侧"短输入增补"指令（P1，改 prompt 不改代码）

在导演 system prompt 中加一条规则：

> 玩家输入按三层解读：① 有明确动作/台词 → 照演；② 输入过短（<15字）→ 由最近一轮的 scene.beat、present 角色与未决张力自动补全合理细节，**不反问、不暂停**；③ 禁止要求玩家复述上一轮环境细节，环境信息由旁白承担。

配合在会话设置里暴露「输入风格」开关（详细描写 / 简短即可），映射到 prompt。**这一条直接治"必须写很长"的病根。**

### 改造 5：叙事瘦身——消息聚合与"对话优先"（P1）

- **聚合渲染**：同一导演拍的 4~6 条消息合并为一个"演出块"，角色台词用对话气泡样式、旁白用衬底样式，视觉上从"日志流"变"漫画格"。
- **导演 prompt 加约束**：单条发言 ≤120 字、每轮台词角色 ≤2 人、旁白 ≤2 段。两场实测中单条 500+ 字、一轮 6 条消息的情况应压掉一半以上。

### 改造 6：新手引导三件套（P2）

1. **开场即建议**：会话首轮（开场白之后）强制生成一次 `actions`——现在是等玩家先输一轮才有，冷启动最懵的一步反而没有扶手。
2. **输入卡壳检测**：输入框聚焦后 15 秒无输入且无建议点击 → 轻提示"卡住了？点上面的方向，或按 💡 让导演换个问法"。
3. **一键推进**：「继续」按钮（发送固定指令 `.`），导演自动按 pending_node / beat 推进下一拍——适合"想看剧情"的轻玩家。

### 改造 7：隐性状态可视化（P2）

导演其实维护着 flags、tension、scene.beat（我在 SSE 里都拿到了），但界面上只有一行地点时间。加一条可折叠的"剧情状态条"：
`当前节拍：灭灯后的僵持 ｜ 张力：卡卡西↔佐助 0.2 ｜ 已获线索：绳结·纸角·第七个`
玩家不再需要靠复述细节来"提醒"系统自己知道什么。

## 三、优先级与验收标准

| 优先级 | 改造项 | 预估成本 | 验收标准 |
|---|---|---|---|
| P0 | 建议动作持久化+恢复 | 后端 1 字段 + 前端 3 行 | 重开会话必现 3 条芯片 |
| P0 | 芯片点击改为预填 | 前端 ~10 行 | 单击预填可改，双击直发 |
| P1 | 意图四键输入条 | 前端 1 天 | 选 tone 后 placeholder 随之变化，payload 带 tone |
| P1 | 导演短输入增补 prompt | 改 preset | 「查脚印」3 字输入也能推进一拍不反问 |
| P1 | 叙事聚合+瘦身 | 前端 1~2 天 + prompt | 单轮 AI 总输出 ≤400 字，台词角色 ≤2 |
| P2 | 新手三件套 | 前后端各 1 天 | 首轮即有建议；「继续」按钮可推进 |
| P2 | 剧情状态条 | 前端 1 天 | flags/tension 可视化折叠展示 |

**北极星指标**：玩家单轮输入字数中位数 103 → ≤20 字；首 5 轮流失率下降；建议芯片点击率 ≥60%。

## 四、一句话总结

这个平台的导演系统其实一直在"替玩家想下一步"（每轮 3 条带语气分类的高质量建议），但产出被丢在了 SSE 流里。**优化主轴不是加新 AI 能力，而是把导演已经想好的答案递到玩家手边**——建议芯片持久化 + 点击预填 + 短输入增补三件事做完，"必须写很长才能推动"的问题就解决了八成。

> 合规声明：本方案为产品设计参考，具体实施请结合平台实际技术栈与团队排期确认。
