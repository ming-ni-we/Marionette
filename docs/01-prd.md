## 0. 一句话定位

**在你的电脑上，15 分钟内从零开始一场带世界书触发与长期记忆的角色扮演——角色卡、世界书、图集全部以本地文件存在，随时导出，换模型不换档。**

拆开这句承诺的三个**可被验证**的成分：
1. **15 分钟内说上第一句话**（首启链路有明确计时口径，见 §9）。
2. **世界书触发 + 记忆摘要默认生效**（不需要用户手搓正则/预设，见 §6 P0）。
3. **资产属于用户**（本地文件仓库，支持 Tavern V2 PNG/JSON 卡与世界书 JSON 导出，见 §6 P0-5）。

不写"极致沉浸""革命性体验"这类不可验证的形容词。

## 1. 问题陈述

**谁在什么场景下遇到了什么痛点？现在怎么解决的？为什么不行？**

- **谁**：中文圈的角色扮演创作者、重度玩家、TRPG 主持人与同人写手。
- **什么场景**：需要"长期、连贯、可自定义"的角色扮演——写一张有世界观的角色卡，开一场能跑上百轮不崩的会话，并给场景配上图。
- **现在怎么解决**：
  - **酒馆系（SillyTavern/RisuAI/Agnai）**：功能强、数据私有，但**上手门槛断崖**——要自己装依赖、配后端、找预设、调世界书、抄正则；社区资源散落在 Discord 小圈子（类脑/旅程社需答题验证）。官方定位原文即"将陡峭的学习曲线视为乐趣的一部分"。
  - **云端产品（Character.AI / 星野 / 猫箱）**：开箱即用，但**长会话记忆断裂**严重（普遍在 15–25 轮后失忆、性格漂移），内容尺度和平台规则随时改（Character.AI 的 NSFW 过滤请愿累计超 17 万签名；筑梦岛因低俗擦边被网信办约谈整改）。
  - **手搓方案（ChatGPT 自定义 GPTs / Claude Projects / Notion + AI）**：零门槛、模型强，但**没有世界书关键词触发、没有会话状态机**，记忆靠模型自身且不可控，格式年际不兼容、跨平台不可迁移。
- **为什么不行**：现有方案把"创作"和"运行"割裂了——能创作的工具门槛高到劝退，开箱即用的工具又拿走了创作主权与记忆控制权。**没有人把"创作者级深度"和"15 分钟上手"合到同一个本地形态里。**

## 2. 目标用户

### 主 Persona
**林澈 / 26 岁 / 独立同人写手（P0 核心用户）**
- 正在写一部 20 万字长篇同人，手里有约 5 万字世界观设定。
- 现在用：Notion 存设定 + ChatGPT 续写 + 本地 Ollama 试水。
- 痛点：ChatGPT 记不住第 1 章的伏笔，每开新会话都要重贴设定；想用酒馆，但被"配 API / 找预设 / 写正则"卡在门外；出图要靠 ComfyUI 单独跑，图散落在文件夹里，和角色对不上号。
- 技术水平：中高（会 Docker、会跑 ComfyUI，但不是程序员）。
- 要的话："设定一次，写完 20 万字不崩，图还能归到角色下面。"

### 次要 Persona
**周雨桐 / 22 岁 / 大学女生 / AI 陪伴重度玩家**
- 从 星野 / 猫箱 迁移而来，每天用 1–2 小时。
- 痛点：云端产品长会话失忆、尺度被吞、平台改规则/下架就全没了（筑梦岛被约谈事件让她没有安全感）。
- 技术水平：低-中（不会写代码，但会照着图文教程操作）。
- 要的话："我的角色在我自己电脑上，想怎么演怎么演，谁也改不了。"

**老张 / 34 岁 / 跑团 DM・TRPG 主持人**
- 带长线战役，需要几十个 NPC + 世界观 + 规则一致性 + 场景图。
- 痛点：酒馆的世界书递归/RAG 要手搓，NPC 一多就管理混乱，立绘截图散落在聊天记录里。
- 技术水平：高（能改源码、会写脚本）。
- 要的话："一个能跑长战役、NPC 有记忆、能顺手出场景图的本地引擎。"

## 4. 竞品差评 → 市场空白（5 条）

1. **上手门槛断崖（最后一公里缺失）**
   酒馆装完不等于能用：还要配后端 API、找预设、抄正则、调世界书。社区吐槽原文——"装完之后怎么跟角色说上话"、"Node.js what now？"、"UI 像有上百万个没解释的按钮的驾驶舱"。资源散落 Discord 小圈子且需答题。**空白：把"酒馆级深度"做成 15 分钟开箱即用。**

2. **记忆断崖 / 长会话断裂**
   Character.AI 普遍在 15–25 轮后忘记名字/人设，被用户总结为"每几条一次幻觉、钉住的记忆被忽略、人格崩塌"；星野/猫箱同样"三天两头失忆、性格大变、串戏"。原因是滑动上下文窗口 + 系统提示被压缩。**空白：把世界书触发 + 自动摘要做成产品化默认能力，而不是让用户手动维护。**

3. **创作者资产被平台绑架，迁移即丢失**
   Chub 转仅加密货币支付，直接把部分地区用户锁死；Character.AI 的卡只能留在本平台；GPTs 格式年际不兼容。更细的是：**一张角色卡只能携带一本世界书**，额外世界书、人格绑定世界书、创作者元数据在迁移时静默丢失，关键词触发机制也无法迁移。**空白：资产以本地文件为单位、可完整导出/导入的"创作者仓库"。**

4. **内容合规与创作自由的矛盾（国内特有）**
   国内产品在监管压力下要么砍内容、要么被约谈/下架（筑梦岛被约谈、星野/猫箱被通报），海外产品因支付与合规无法服务国内。**本地自部署是唯一能同时满足"合规可控 + 创作自由 + 数据私有"的形态，但现有本地方案（SillyTavern）本身完全没有内容审核层。** 空白：内置一个可配置、可关闭的内容安全审核层。

5. **图集/美术资产与运行时脱节**
   酒馆的出图与图集管理依赖第三方插件，角色一致性难保证，生成图散落在聊天记录里，没有"以角色为中心"的素材库。**空白：创作产物（卡 + 世界书 + 预设 + 图集）以"角色"为单位统一归档，运行时可顺手往角色图集里存场景图。**

## 5. 我们的差异化

**用户为什么选我们而不是酒馆/云端产品？**

| 对比维度 | SillyTavern | Character.AI / 星野 | 我们 |
|----------|-------------|---------------------|------|
| 上手成本 | 30 分钟–2 小时 | 0 | **首启 15 分钟内说上第一句话（向导化）** |
| 记忆控制 | 强但要手调 | 弱且不可控 | **世界书触发 + 自动摘要默认生效** |
| 资产归属 | 本地（但分散） | 平台 | **本地角色仓库，卡/世界书/图集一键导出** |
| 内容审核 | 无 | 强制且多变 | **可选、可配置的本地审核层（面向国内合规）** |

一句话差异：**我们不做"功能最多的前端"，我们做"从装好到入戏最快、且资产真正属于你"的那一个。**

## 7. MVP 范围 与 Out-of-Scope

### 7.1 MVP 范围（P0，逐条可验收）
1. Docker 一键起（含 Windows 一键启动脚本 + 启动自检），首启进入向导。
2. 首启向导：接入一个 LLM 后端（本地或云 API），点"测试连接"给明确成败与错误原因。
3. 角色卡编辑器：字段齐全，支持从 PNG/JSON 导入与导出。
4. 世界书编辑器：关键词触发条目，支持按角色绑定，支持多本世界书并存（补足"一张卡只带一本"的坑）。
5. 运行时：会话状态机 + 上下文装配 + 世界书触发注入 + 自动摘要记忆。
6. 会话管理：多会话、重 roll/分支、导出。
7. 场景出图：检测到本机 ComfyUI 即提示连接，出图后一键存入该角色图集。
8. 内容安全审核层：输入/输出双端审核，规则可配置、可在自部署场景关闭。
9. 最简埋点 + 本地自诊断日志（不上报隐私）。
10. 内容库搜索与筛选：角色卡/世界书/预设/图集列表页支持关键词搜索、标签筛选与排序（F16，P0）。

### 7.2 Out-of-Scope（带原因 + 何时考虑）
| 项目 | 原因 | 何时考虑 |
|------|------|----------|
| 广场（发现/浏览他人卡） | 社交侧，不属创作→运行闭环；且需服务端与运营 | v2（有待分发的内容再上） |
| 群聊 / 多角色同台 | 运行时复杂度高，非最小闭环 | v2 |

| 多租户 / 账号体系 | 用户已明确 v1 不做（单机自部署） | 二期上云时 |
| 云端同步 / 多端 | 同上 | 二期 |
| 原生移动端 App | 与"本地自部署优先"冲突；移动端体验另立项 | 有明确需求后 |
| 语音 TTS / Live2D / 动态立绘 | 非创作→运行核心 | v2 或 v3 |

| 跨会话历史全文检索（F15） | 单机小数据量下价值有限 | v2（注：内容库搜索与筛选 F16 仍在 P0，二者范围不同） |

## 9. 关键问题：「第一次 15 分钟」链路

**从拿到安装包/仓库 → 到第一次和角色真正说上话，共 6 步：**

| 步 | 动作 | 用户操作 | 最易流失点 | 对策 |
|----|------|----------|-----------|------|
| 0 | 获取 | 拉取仓库 / 下载安装包 | 找不到入口 | 提供 Windows 一键启动包 + 图文首启页 |
| 1 | 起服务 | 双击启动脚本 / `docker compose up` | Docker 没装、端口冲突 | 启动自检：缺依赖/端口占用给明确中文报错与修复指引 |
| 2 | **接入 LLM** | 向导里填一个后端 | **最大流失点** | 一键接入本机 Ollama/LM Studio；或粘贴云 API key；"测试连接"给明确成败 + 错误分类（模型名错/端点缺 /v1/余额为 0） |
| 3 | 选/导入第一个角色 | 用内置示例卡或导入自己的卡 | 空白页不知点哪 | 内置 3–5 张带世界书+预设的官方示例卡；"导入 PNG/JSON"一键就绪 |
| 4 | 开一场会话 | 点"开始对话" | 不知道要配什么 | 默认预设即开即聊，世界书触发与摘要默认开启 |
| 5 | 场景出图 | 一键连 ComfyUI（若已部署） | 不知要连哪个地址 | 自动探测 `http://127.0.0.1:8188`，一键连接，出图自动归档 |

**结论**：
- **最容易流失的一步是第 2 步（LLM 接入）**——酒馆正是死在这里。所以要把它从"配一整套后端"压缩成"向导里填一项 + 明确自检"。
- **该链路会导致以下功能降级**：
  1. **"多后端/多模型管理面板"从 P0 降为 P1**——MVP 只做"一个能跑通的默认后端 + 向导"，多后端后置。
  2. **ComfyUI 从"完整工作流编辑器"降为"检测 + 出图 + 归档"轻量钩子**——完整工作流编辑器进 v2。
  3. **记忆系统从"向量检索/RAG"降为"世界书触发 + 自动摘要"**——验证"记忆默认生效"假设后，再做 P1 的向量增强。
- **不会降级的**：世界书触发、自动摘要、资产导入导出、内容审核——它们是差异化承诺的核心，必须进 P0。

## 10. 验收标准（Given / When / Then）

- **Given** 用户首次启动且本机已装 Docker，**When** 双击启动脚本，**Then** 服务在 60 秒内就绪并自动打开向导页，失败时给出中文原因与修复步骤。
- **Given** 用户在向导中接入一个可用 LLM 端点，**When** 点击"测试连接"，**Then** 3 秒内返回成功并把该后端设为默认；失败时归类错误（模型名/端点/额度/网络）。
- **Given** 用户导入一张 Tavern V2 PNG 角色卡，**When** 进入编辑页，**Then** 卡内字段（描述/人格/开场白/示例对话/头像）完整还原。
- **Given** 用户为角色绑定一本含"酒馆"关键词的世界书，**When** 会话中说"我们去酒馆吧"，**Then** 对应条目内容出现在注入上下文，且角色回复体现该设定。
- **Given** 会话已进行 60 轮，**When** 用户询问第 3 轮提过的设定，**Then** 角色能正确回忆（由摘要/记忆召回）。
- **Given** 本机 ComfyUI 运行中，**When** 用户点击"画这一场景"，**Then** 出图成功并自动归档到当前角色图集。
- **Given** 审核层为开启状态，**When** 用户输入命中违规规则的内容，**Then** 请求被拦截并给出中性提示，不产生 LLM 调用；关闭审核层后不再拦截。
- **Given** 用户导出角色，**When** 选择导出，**Then** 生成的可移植文件包含卡 + 绑定世界书 + 预设，可在另一实例完整还原。

## 11. 边界条件（5 态覆盖 + 边界）

| 类别 | 要求 |
|------|------|
| 空状态 | 无角色/无会话/无图集，均展示引导与示例，不显示空白页 |
| 加载状态 | LLM 生成中显示进度指示 + 中止按钮 + 预计耗时 |
| 错误状态 | 按模型/网络/权限/额度分类，给降级方案与重试入口 |
| 边界值 | 超长上下文截断提示；单卡/世界书条目数上限；图片分辨率与体积上限 |
| 并发 | 单实例多会话并存；出图与对话互不阻塞 |
| 离线 | LLM 为本地模型时全离线可用；云端后端断网时给明确提示并保留草稿 |
| 权限拒绝 | 文件读写/端口占用/ComfyUI 连接被拒，给明确中文原因 |
| 内容安全 | 命中审核规则的极端情况（自伤/未成年保护）走强拦截 + 中性提示 |

## 13. 数据埋点方案

MVP 必须埋点（不埋 = 上线后无法验证产品假设）。**单机自部署场景下默认本地落盘、匿名，不做任何云端上报；用户可一键导出诊断包。**

| 事件类别 | 必埋事件 | 说明 |
|----------|----------|------|
| 获客/启动 | `app_start`, `wizard_start`, `wizard_step_view`, `wizard_complete` | 首启链路漏斗与耗时 |
| 激活 | `llm_backend_connected`, `character_created`, `worldbook_created`, `first_message_sent` | 关键激活点与"15 分钟"计时口径 |
| 留存 | `session_start`, `session_duration`, `message_count_per_session` | 使用频次与时长 |
| 核心价值 | `worldbook_entry_triggered`, `memory_recall_hit`, `image_generated` | 验证世界书触发/记忆/出图假设 |
| 异常 | `error_occurred`（前端 + API 分类）, `crash` | 稳定性与错误分布 |

**实现要求**
- 事件命名规范：`{对象}_{动作}`（如 `character_created`, `worldbook_entry_triggered`）。
- 属性规范：每个事件附带 `session_id`, `timestamp`, `device`, `app_version`；**不采集原始输入内容、不上报 IP**。
- 提供本地日志查看与导出，便于用户自查与提 bug。

## 14. 3 个候选产品名

> 已对 AI 角色扮演/陪伴赛道做同名排查（已确认占用：幕间、织界 WorldLoom、戏格、月匣、猫箱、星野、筑梦岛、皮影客、影艺、千面系列等，均已排除）。正式定名前仍需做一次商标与各应用商店的正式检索（法务步骤）。

1. **「窑」（英文名 Kiln）**
   - 理由：创作 = 塑形，运行 = 烧制，出图 = 出窑，三段一体，恰好对应"创作工作室 → 运行时引擎 → 图像生成"的产品结构；单字品牌辨识度高，赛道内未见同名。
2. **「提线」（英文名 Marionette）**
   - 理由：创作者掌线、AI 登台，"线"隐喻世界书/预设对运行的驱动；同时暗含"数据与资产在你手里"的掌控感；赛道内未见同名。
3. **「台本」（英文名 Script）**
   - 理由：直白传达"写台本（创作）→ 开演（运行）"；**注意**：属通用词，商标注册难度较高，建议作为备选，若采用需搭配图形商标。

## 15. 给架构师 / 设计师的信息（协作交接）

**给架构师（约束，不是选型）**：
- 形态约束：v1 Docker 一键起，单机自部署，无账号体系；分层需支持二期上云（存储/运行时/前端解耦）。
- 需支撑的实体：角色卡（Tavern V2 兼容）、世界书、预设、会话状态、记忆/摘要、角色图集、审核规则。
- 运行时的关键机制：会话状态机 + 上下文装配顺序 + 世界书触发（含递归）+ 摘要记忆，需可观测（便于验证触发器）。
- 审核层需可插拔、可关闭；出图钩子需能探测本机 ComfyUI 默认端口。
- 需向设计师提供"首启向导"的状态（成功/失败/分类错误）枚举。

**给设计师（设计需求）**：
- 核心界面：**首启向导**（最关键，直接决定 15 分钟承诺成败）、创作工作室（卡/世界书/预设）、运行时聊天页、角色图集页、**内容库列表页**。
- **内容库列表页必须带搜索框与筛选器**（关键词搜索 + 标签筛选 + 排序），这是 P0 功能 F16；空状态需给出新建/导入引导。
- 情感基调：面向创作者与重度玩家，专业但不高冷；避免 AI 模板味（无 "Welcome to..." / "Lorem ipsum" / "Sign up today" 类占位）。
- 图标：统一 SVG 图标库，用文字语义描述（如"世界书=书本图标""运行时=播放图标"），**禁止使用 emoji 作功能图标**。
- 配色：避免紫色→粉色渐变主视觉。
- 必须覆盖 5 态：空/加载/错误/有数据/边界；尤其是"无角色""无会话""未连后端"的空状态引导。
